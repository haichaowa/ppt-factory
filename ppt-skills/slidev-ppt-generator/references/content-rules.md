# PPT 内容组织规则

本文档定义如何将用户输入的文字内容组织为优秀的 Slidev 演示文稿。

---

## 一、核心原则

### 1. 一页一观点
- 每张幻灯片只传达一个核心观点
- 避免信息过载
- 观众一次只能记住 3-5 个要点

### 2. 金字塔原理
- **结论先行**：先说核心观点，再说支撑论据
- **以上统下**：上层观点统领下层论据
- **归类分组**：相关内容放在一起

### 3. 少即是多
- **文字精简**：每页不超过 50 字（中文）
- **要点控制**：3-5 条为佳
- **留白呼吸**：适当留白让内容透气

---

## 二、页面数量建议

| 演讲时长 | 推荐页数 | 说明 |
|---------|---------|------|
| 3-5 分钟 | 6-10 页 | 短分享，内容精简 |
| 5-10 分钟 | 10-15 页 | 中等长度，适当展开 |
| 10-20 分钟 | 15-25 页 | 深入讲解 |
| 20-40 分钟 | 25-45 页 | 完整演讲 |

---

## 三、标准结构模板

```
1. 封面页（1页）
2. 目录页（1页，可选）
3. 章节 1（1页章节分隔 + N页内容）
4. 章节 2（1页章节分隔 + N页内容）
5. 章节 3（1页章节分隔 + N页内容）
6. ...
7. 结束页（1页）
```

## 四、内容特征 → Slidev 布局映射

| 原始内容特征 | 推荐布局 | Frontmatter 配置 |
|-------------|---------|-----------------|
| 演讲标题 + 副标题 | `center` | `layout: center` |
| 章节分隔/编号切换 | `section` | `layout: section` |
| 观点 + 3-5 论据 | `default` | （默认布局） |
| 对比/优缺点分析 | `two-cols` 或 `comparison` | `layout: two-cols` + `::right::` / 自定义卡片 |
| 带标题的对比 | `two-cols-header` | `layout: two-cols-header` + `::left::`+`::right::` |
| 图片+文字说明 | `image-left/right` | `layout: image-left` + `image: 路径` |
| 全屏图片 | `image` | `layout: image` + `image: 路径` |
| 嵌入网页演示 | `iframe` | `layout: iframe` + `url: 网址` |
| 代码演示 | `default` | 代码块 + 行高亮 |
| 代码逐段讲解 | `code-focus` | 左代码 + 右注释栏 |
| 特性/功能列举 | `card-grid` | UnoCSS grid + 卡片组件 |
| 多步骤流程/管道 | `steps-pipeline` | 水平步骤卡片 + 箭头 |
| 新旧方案/技术选型 | `comparison` | 双栏卡片 + 代码块 |
| 技术演进/版本迭代 | `timeline` | 纵向时间线 + 圆点 |
| 系统架构/分层 | `architecture` | 分层卡片 + 层间箭头 |
| 关键指标/数据 | `metrics` | 大数字 + 说明文字 |
| Benchmark/参数对比 | `data-table` | Markdown 表格 |
| 问答/互动环节 | `faq` | Q/A 卡片逐个展开 |
| API 参数/配置详解 | `annotated-list` | 左参数名 + 右说明 |
| 名言金句 | `quote` | `layout: quote` |
| 关键数据展示（单个） | `fact` | `layout: fact` |
| 核心结论陈述 | `center` 或 `statement` | `layout: statement` |
| 演讲者介绍 | `intro` | `layout: intro` |
| 结束致谢 | `end` | `layout: end` |

## 五、Slidev 内容增强技巧

### 渐进展示（v-click）
用 `v-click` 指令逐步揭示内容，避免一次性呈现太多信息：
```html
<div v-click>第一个要点</div>
<div v-click>第二个要点</div>
<div v-click>第三个要点</div>
```

或使用 `<v-clicks>` 组件自动为列表项添加动画：
```html
<v-clicks>
- 要点一
- 要点二
- 要点三
</v-clicks>
```

### 双栏布局
使用 `::right::` 插槽创建对比页：
```markdown
---
layout: two-cols
---
# 左侧标题
左侧内容

::right::
# 右侧标题
右侧内容
```

### 代码高亮
使用行号高亮和点击式高亮：
````markdown
```ts {1,3-5}
// 第1行和第3-5行高亮
const name = 'slidev'
const version = '1.0'
const description = 'slides for developers'
```
````

点击式逐步高亮：
````markdown
```ts {1|2-3|all}
// 点击1: 只高亮第1行
// 点击2: 高亮第2-3行
// 点击3: 高亮所有行
```
````

### 演讲者备注
在幻灯片末尾使用 HTML 注释添加备注：
```markdown
# 标题

内容

<!-- 这段是演讲者备注，只在演示者视图中显示 -->
```

### 过渡动画
在 frontmatter 中指定幻灯片过渡效果：
```yaml
---
transition: fade-out
---
```

可选值：`fade`、`fade-out`、`slide-left`、`slide-right`、`slide-up`、`slide-down`、`zoom`

## 八、硬性设计约束（验证阶段强制检查）

> **借鉴**：rhuss/cc-slidev 的"证据级设计"理念——Miller 定律 + WCAG 可访问性 + 字号下限。
> 与上面的"内容建议"不同，本节约束**必须在生成阶段强制满足**，超限时**自动拆页或迁移内容**，不允许靠 LLM 自觉。

### 8.1 约束矩阵

| 编号 | 约束 | 阈值 | 触发动作 | 理由 |
|------|------|------|---------|------|
| C-01 | 单页要点数 | ≤ 6 条 | 超限 → 自动拆为两页，outline.md 标注 `splitFrom: <原页号>` | Miller 定律 7±2，取下限确保理解 |
| C-02 | 单页中文字数 | ≤ 50 字（正文） | 超限 → 移至演讲者注释 `<!-- ... -->` | 一页一观点，文字过密无法扫读 |
| C-03 | 最小字号 | ≥ 18pt（正文） / ≥ 28pt（标题） | 超限 → 拆页或缩减内容 | 后排观众可读性下限 |
| C-04 | 对比度 | ≥ 4.5:1（正文）/ ≥ 3:1（大字号） | 不达标 → 调整配色（使用 `text-{color}-{shade}` 重新选） | WCAG AA 可访问性标准 |
| C-05 | 单页元素总数 | ≤ 6 个（含图标/卡片/代码块/标题） | 超限 → 拆页 | 视觉聚焦上限 |
| C-06 | 标题性质 | **必须断言式**（含动词或数字） | 描述式标题 → 改写为判断句 | 标题应承载结论，而非标签 |
| C-07 | 代码块行数 | ≤ 15 行 | 超限 → 必须设置 `{maxHeight:'350px'}` | 避免代码溢出幻灯片高度 |
| C-08 | 卡片网格密度 | 最多 3×3（9 卡） | 超限 → 拆为两页 card-grid | 视觉密度上限 |

### 8.2 标题断言式示例

| ❌ 描述式（不达标） | ✅ 断言式（达标） |
|------|------|
| 关于 Docker 的介绍 | Docker 让容器化部署变得可移植 |
| 性能对比 | 新方案 P99 延迟降低 60% |
| React 19 新特性 | Compiler 自动消除 useMemo 需求 |
| 系统架构 | 三层架构支撑 10K QPS |

### 8.3 自动拆页规则

当 outline.md 中某页触发 C-01 或 C-05 时，`ppt-structure-analyst` 必须自动拆为两页：

```markdown
## 第 N 页：原标题（拆分前）

- **Pattern**：card-grid
- **splitFrom**: null
- **核心内容**：（7 条要点 —— 触发 C-01）

拆分为 ↓

## 第 N 页：原标题（上）—— 要点 1-4
- **Pattern**：card-grid
- **splitFrom**: original-N
- **核心内容**：（4 条要点）

## 第 N+1 页：原标题（下）—— 要点 5-7
- **Pattern**：card-grid
- **splitFrom**: original-N
- **核心内容**：（3 条要点）
```

### 8.4 字号对照表（UnoCSS → pt）

| UnoCSS | pt | 用途 | 是否达标 |
|--------|-----|------|---------|
| `text-xs` | 12pt | 注释、标注 | ❌ 仅用于次要注释 |
| `text-sm` | 14pt | 描述文字 | ❌ 仅供脚注 |
| `text-base` | 16pt | 正文（边缘） | ⚠️ 不推荐正文 |
| `text-lg` | 18pt | **正文下限** | ✅ 达标 C-03 |
| `text-xl` | 20pt | 次要标题 | ✅ |
| `text-2xl` | 24pt | 卡片标题 | ✅ |
| `text-3xl` | 30pt | **页面标题下限** | ✅ 达标 C-03 |
| `text-4xl` ~ `text-6xl` | 36-60pt | 封面、大数字 | ✅ |

### 8.5 对比度快速检查

生成 slides.md 后，对每页的「正文文字 + 背景」组合做对照：

| 背景色 | 推荐正文色 | 对比度（约） | 达标 |
|--------|-----------|------------|------|
| `bg-black` / `bg-gray-900` | `text-white` | 21:1 | ✅ |
| `bg-black` / `bg-gray-900` | `text-gray-100` / `text-white/80` | 16:1 | ✅ |
| `bg-black` | `text-gray-400` | 4.5:1 | ✅ 边缘 |
| `bg-black` | `text-gray-500` 及更暗 | < 4.5:1 | ❌ 失败 |
| `bg-violet-900/20`（半透明） | `text-violet-100` / `text-white` | > 10:1 | ✅ |
| `bg-white` | `text-gray-500` 及更暗 | > 7:1 | ✅ |

- [ ] 每页要点数 ≤ 6（C-01）

- [ ] 标题为断言式（C-06）

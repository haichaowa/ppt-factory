## 第 9 页：探索 -> 规划 -> 编码 -> 提交

- **Pattern**：`steps-pipeline`
- **章节**：工作流优化
- **核心内容**：
  - 四阶段工作流：探索 -> 规划 -> 实现 -> 提交
  - 探索：Plan Mode 只读文件，不做修改
  - 规划：制定详细实现方案，Ctrl+G 编辑计划
  - 实现：Normal Mode 按计划编码并验证
  - 提交：描述性 commit + 创建 PR
- **布局细节**：
  - steps-pipeline 水平四步流程
  - 4 个步骤卡片：探索、规划、实现、提交
  - 每步配一个图标和一行描述
  - 底部小字提示：能用一句话描述 diff 的简单任务，跳过规划
- **备注**：用紧凑变体（去掉大图标区域），因为步骤较多

## 第 15 页：CLAUDE.md 写什么

- **Pattern**：`comparison`
- **章节**：环境配置
- **核心内容**：
  - 应包括：Bash 命令、非默认代码风格、测试指令、仓库礼仪、架构决策、环境怪癖、常见陷阱
  - 不应包括：代码可推断的信息、标准语言约定、详细 API 文档、频繁变化的信息、长篇教程
- **布局细节**：
  - comparison 布局
  - 左栏（绿色）：应包括的内容，7 个要点
  - 右栏（橙色/红色）：不应包括的内容，5 个要点
  - 各用简短关键词，不要长句
- **备注**：左右两栏内容较多，每个条目控制在 2-4 字

## 第 18 页：尽早且频繁地纠正方向

- **Pattern**：`default`
- **章节**：会话管理
- **核心内容**：
  - Esc：中途停止，保留 context 后重定向
  - Esc+Esc 或 /rewind：恢复之前的对话和代码状态

  - /clear：不相关任务间重置 context
- **布局细节**：
  - 标题：快速纠正，保持方向
  - 4 个操作用列表呈现，每项 = 快捷键/命令 + 一句话说明
  - 底部强调：同一问题纠正两次以上，/clear 重新开始
- **备注**：可以配合键盘图标的视觉元素

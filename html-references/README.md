# html-references · 体系化 HTML 范例库

每天从 GitHub / 设计网站搜集**已成体系**的 HTML 范例或模板（多页面、多组件、
有统一设计系统的完整作品），完整下载到本地，作为 PPT Factory 的外部参考资产。

## 与其他目录的分工

| 目录 | 定位 |
|------|------|
| `html-references/` | 外部**成体系范例**的完整归档（多模板、多组件、系统化） |
| `web-clones/` | 单个优秀网站的**风格复刻**（学语言，不搬代码） |
| `examples/` | 本仓库自己的金样与质量锚点 |
| `patterns/` / `templates/` | 沉淀后的可复用资产（只放提炼结果，不放外部源码） |

## 收录标准（缺一不可）

1. **成体系**：至少 3 个页面/模板或 10 个组件，有统一设计语言；
2. **质量高**：版式、层级、间距、响应式达到专业水准；
3. **许可证清晰**：MIT / Apache / CC BY / 公共领域等允许本地留存学习；必须记录原文 license；
4. **可运行**：下载后零构建或极简构建即可浏览；
5. **体量克制**：源码 < 200MB，不含 node_modules / 构建产物；
6. 宁缺毋滥：当天没有达标的对象，就在日志里记录考察过的候选和淘汰原因，**不收录凑数**。

## 每日产出结构

```text
html-references/collections/YYYY-MM-DD-name/
├── source/          # 完整源码（浅克隆或压缩包）
├── screenshots/     # 代表性页面截图
├── meta.md          # 来源、license、版本/commit、下载方式、体积
├── notes.md         # 体系拆解：结构清单、设计系统、组件清单、可复用结论
└── preview.md       # 本地如何打开、哪些页面最值得先看
```

## notes.md 必须回答

- 这套范例的**设计系统**：色板、字体、间距、组件规范；
- **体系结构**：页面/组件如何组织，哪些模式可迁移到 PPT；
- **可复用结论**：哪些做法值得进入 `patterns/`（只写建议，不改源码）；
- **质量评价**：优点、局限、适合的演示场景。

## 安全与版权规则

- 每条收录必须保留原仓库的 LICENSE 文件与作者署名；
- 只做本地学习归档，不二次分发、不删改版权声明；
- 许可证不明确或禁止再分发的一律不收；
- source/ 冻结快照，不做任何修改；提炼结论只写在 notes.md。

# AUDIENCE-BRIEF — 生成前的观众与叙事定义

所有引擎共用。HTML 引擎在 `docs/WORKFLOW.md` 第 1 步产出；Slidev 引擎创建模板前产出。若用户已给完整信息，可引用原文，不允许编造观众假设。

## 必填字段

```md
### Audience brief
- 观众：
  - 身份与人数：
  - 已知 / 未知：
  - 决策权与关注点：
- 场景：
  - 演讲场合与时长：
  - 屏幕环境：投影 / 显示器 / PDF 阅读 / 混合
  - 讲述方式：现场讲 / 录屏 / 自阅读
- 目标：
  - 核心主张（一句完整话）：
  - 期望观众行动 / 判断：
  - 最需要拆掉的一个误解：
- 叙事：
  - 叙事线：decision / teaching / technical-review / product-story / research
  - 开场张力：
  - 关键证据：
  - 结尾回收：
- 内容边界：
  - 术语处理：
  - 必须保留的信息：
  - 必须删除的信息：
  - 高风险问题与回应：
```

## 叙事线选择

| 叙事线 | 适用 | 最小骨架 | 关键证据 |
|---|---|---|---|
| decision | 决策 / 汇报 / 评审 | 问题 → 约束 → 选项 → 取舍 → 建议 → 下一步 | 成本、风险、收益、反例 |
| teaching | 教学 / onboarding | 已知场景 → 新概念 → 示范 → 练习 / 误区 | 对比示例、步骤、常见错误 |
| technical-review | 技术方案 / 架构评审 | 目标 → 现状 → 方案 → 权衡 → 验证 → 风险 | 架构图、边界条件、数据、失败案例 |
| product-story | 产品 / 用户价值 | 用户处境 → 冲突 → 方案 → 体验差异 → 证明 | 用户原话、前后对比、可验证指标 |
| research | 学术 / 研究 | 问题 → 方法 → 发现 → 解释 → 局限 → 意义 | 图表、方法可信度、不确定性 |

## 标题写法：主张句优先

| 不推荐 | 推荐 |
|---|---|
| 用户增长方案 | 3 个入口改动能降低首周流失 |
| 架构对比 | 单写入队列无法满足峰值吞吐 |
| 实验结果 | 延迟下降来自缓存命中率提升 |
| 项目背景 | 当前流程的主要成本在人工审核 |

主题词标题只用于封面、章节页、目录页；论证页标题应尽量表达结论。

## 验收标准

- [ ] 核心主张是一句可被反对、可被证据支持的完整话
- [ ] 观众已知 / 未知写得具体，不使用“相关人员”这类泛称
- [ ] 期望行动可执行，且能在结尾页回收
- [ ] 关键证据已标注来源；无来源时不使用 metrics / table
- [ ] 叙事线覆盖主要反驳或风险
- [ ] PDF 自阅读与现场讲述的密度差异已明确
